# AMA Earth Live Build — Parcel Boundary Automation

## The Task

Automate parcel boundary mapping for aerial photographs. Currently done manually: someone draws property boundaries onto historical aerial maps by hand. We replace that with an automated system.

**Input:** Aerial map PDFs + property address
**Output:** Same PDFs with parcel boundaries drawn on top automatically
**Data source:** Regrid API for parcel boundary GeoJSON polygons

## Stack

- **Framework:** Next.js 14+ (App Router, TypeScript)
- **Styling:** Tailwind CSS
- **Database:** Supabase (Postgres + Storage)
- **Parcel Data:** Regrid API v2 (GeoJSON parcel boundaries)
- **PDF Processing:** `pdf-lib` (read/write PDFs), `pdf-to-img` or `pdf2pic` (render pages as images)
- **Image Processing:** `sharp` (overlay drawing, compositing)
- **Mapping:** Leaflet + React-Leaflet (interactive map display)
- **LLM:** OpenRouter API (for vision-based coordinate estimation if needed)
- **Geocoding:** Nominatim / Google Geocoding API (address to lat/lng)
- **Deployment:** Vercel (auto-deploy on push to `main`)

## Pipeline (How It Works End to End)

1. **User enters property address** → geocode to lat/lng
2. **Query Regrid API** with lat/lng → get parcel boundary GeoJSON polygon
3. **User uploads aerial PDF** → store in Supabase storage
4. **Render each PDF page** as a PNG image
5. **Display results:**
   - Interactive map (Leaflet) showing the parcel boundary polygon
   - Aerial photo pages as images
   - Side-by-side view: aerial photo + map with boundary
6. **Overlay boundary on aerial photos** (stretch goal):
   - Use coordinate mapping (if geographic extent is known)
   - Or use vision model to estimate property location on the aerial
   - Draw the polygon on each image using Sharp/Canvas
7. **Export:** Reassemble annotated images into a new PDF for download

## Regrid API Reference

**Endpoint:** `https://app.regrid.com/api/v2/parcels/query`
**Auth:** Token parameter: `?token=YOUR_TOKEN`

**Search by address:**
```
GET https://app.regrid.com/api/v2/parcels/address?query=123+Main+St+City+ST&token=TOKEN
```

**Search by lat/lng:**
```
GET https://app.regrid.com/api/v2/parcels/point?lat=40.7128&lon=-74.0060&token=TOKEN
```

**Response:** GeoJSON FeatureCollection. Each Feature has:
- `geometry`: Polygon or MultiPolygon (the parcel boundary coordinates)
- `properties`: Address, owner, parcel number, acreage, land use, etc.

The geometry coordinates are [longitude, latitude] pairs forming the boundary polygon.

## Supabase Schema

```sql
CREATE TABLE projects (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  name TEXT,
  address TEXT NOT NULL,
  latitude DOUBLE PRECISION,
  longitude DOUBLE PRECISION,
  parcel_geojson JSONB,
  status TEXT DEFAULT 'created',
  created_at TIMESTAMPTZ DEFAULT now()
);

CREATE TABLE aerial_pages (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  project_id UUID REFERENCES projects(id),
  page_number INTEGER NOT NULL,
  original_image_url TEXT,
  annotated_image_url TEXT,
  year_label TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);
```

## Key Technical Decisions

- **pdf-lib** for PDF manipulation (reading structure, creating new PDFs)
- **Sharp** for image processing (drawing polygons, compositing)
- **Leaflet** for map display (open source, no API key needed for tiles)
- **Regrid** for parcel data (Isiah specifically mentioned this)
- Supabase Storage for file uploads and processed images
- Keep processing server-side (API routes) to handle large PDFs
