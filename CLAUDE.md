# Earth — AMA Earth Live Build Scaffold

## What This Is

This is a pre-built scaffold for a 1-hour live coding interview with Isiah Cruz, CEO of Ama Earth Group. The project emulates the core architecture of AMA Earth's product: AI-powered Phase I Environmental Site Assessment (ESA) report generation. Everything is pre-wired so the builder can focus on the roadmap item, not infrastructure setup.

The scaffold includes working PDF text extraction, LLM-powered summarization via OpenRouter, Supabase storage + database, and a UI that emulates AMA Earth's homepage with an added "Assessments" tab as the live demo surface. When a new roadmap item lands, the builder extends what's already here.

## Stack

- **Framework:** Next.js 16 (App Router, TypeScript) — see `AGENTS.md`, this is not the Next.js you were trained on; consult `node_modules/next/dist/docs/` if anything looks off (e.g., `params`/`searchParams` are Promises now)
- **Styling:** Tailwind CSS v4 (CSS-based `@theme` config in `globals.css`, no `tailwind.config.ts`)
- **Database:** Supabase (Postgres)
- **File Storage:** Supabase Storage (bucket: `uploads`)
- **LLM:** OpenRouter API (model-agnostic, defaults to `anthropic/claude-sonnet-4-5`)
- **PDF Processing:** `pdf-parse` for text extraction
- **Deployment:** Vercel (auto-deploy on push to `main`)
- **Package Manager:** npm

## Supabase Schema

See `supabase/schema.sql`. Tables: `documents`, `assessments`, `assessment_documents`. Storage bucket: `uploads`.

## How The Pipeline Works

1. User opens `/assessments`
2. User uploads a PDF via drag-and-drop
3. `/api/upload` sends file to Supabase storage, creates `documents` row with status `uploaded`
4. Client triggers `/api/extract` which downloads the file, runs pdf-parse, stores `raw_text`, sets status `extracted`
5. User clicks "Generate Report" — `/api/generate` sends `raw_text` + ESA prompt to OpenRouter, stores structured JSON in `report` column, sets status `complete`
6. `ReportViewer` renders the report sections with citations
7. Realtime status updates via Supabase Realtime subscription on the `documents` row

## AMA Earth Product Context

AMA Earth builds the "operating system for environmental consultants." Their product **Squid** takes messy document sets (city directories, Sanborn fire insurance maps, aerial photographs, regulatory database exports, environmental lien searches) and generates structured Phase I ESA report sections following ASTM E1527-21 federal standards plus state regulatory overlays (NJDEP, TCEQ, FDEP, etc.).

Key product features:
- Document upload (up to 100 files per project, 250 free credits)
- Pipeline states: Submit docs → Under review → Drafting in progress → Draft ready
- Voice notes and dictation for consultant input
- Citation tracking back to source documents
- Report template customization per client
- Human review loop (every output reviewed before delivery)

The accuracy bar is 100%, not 95%. Environmental reports are legal documents.

See `ESA_DOMAIN.md` for full terminology and report structure reference.

## Coding Conventions

- TypeScript strict mode
- Server components by default; client components only when needed
- API routes in `src/app/api/` using Next.js Route Handlers
- Error handling: try/catch with meaningful error messages, never silent failures
- Console.log progress during processing so the observer can see what's happening
- Commit frequently with descriptive messages
- No placeholder code: every function does real work or throws "not implemented yet"

## Agent Commands

Run these in separate Claude Code chat windows for parallel work:

- `/plan` — Planning agent. Use FIRST when you receive a new roadmap item. It interviews you, writes a phased plan to `PLAN.md`, then you execute.
- `/test` — Test agent. Kick off in a second terminal. Reads codebase, writes tests, runs them, reports failures.
- `/review` — Review agent. After building a feature, run this to check quality, catch issues, suggest improvements.
- `/observe` — Observer agent. Chat with it anytime. It reads the codebase and answers questions about what exists, what's connected, what's missing.

## Key Reminder

This scaffold exists so the builder never touches infrastructure during the live build. Supabase is connected. OpenRouter is connected. Vercel deploys on push. Upload → extract → generate works end-to-end. When a roadmap item arrives, focus on the feature, not the plumbing.

The repo name is `earth` (intentionally generic) — the UI is an AMA Earth homepage clone for demo continuity, but the codebase is the builder's working clone, not AMA's actual codebase.
